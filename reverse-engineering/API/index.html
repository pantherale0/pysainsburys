    Sainsbury's GOL API Reference¶

    Static analysis of app v3.65.0 (com.sainsburys.gol). Live traffic validated 2026-08-30 — see PHASE1.md.

    Architecture overview¶

    The app uses multiple HTTP backends with Retrofit (OkHttp) and Ktor clients:

    Host Role
    https://www.sainsburys.co.uk Primary grocery API (/groceries-api/gol-services/...)
    https://gol-app-bff-commerce.int.prd.jspaas.uk BFF proxy for basket/checkout/slot/order (feature-flagged)
    https://gol-app-bff-homepage.int.prd.jspaas.uk BFF proxy for homepage data
    https://account.sainsburys.co.uk OAuth 2.0 / OpenID Connect identity provider
    https://api.gs.sainsburys.co.uk SmartShop in-store API (/shop/api/v1/...)
    https://golapp-config.s3.amazonaws.com Remote app config (/android/prod/config.json)
    https://www.sainsburys.co.uk/smartlists/v1 Smart lists

    Most grocery endpoints share the path prefix:

    https://www.sainsburys.co.uk/groceries-api/gol-services/{service}/v{N}/...

    When the BFF feature flag is enabled, an OkHttp interceptor rewrites select paths from /groceries-api/gol-services/{slot,basket,checkout,order}/... to the BFF commerce/homepage hosts, stripping the /groceries-api/gol-services/ prefix.

    Authentication¶

    OAuth clients¶

    Channel Client ID Redirect URI Extra authorize params
    Android app gol-android sainsburys://oauth/redirect-login missionId=gol, audience=gol.sainsburys.co.uk, channel=Android, appVersion=<version>
    Desktop web (gol-ui) gol https://www.sainsburys.co.uk/gol-ui/oauth/redirect missionId=gol, audience=gol.sainsburys.co.uk, response_mode=query

    Shared settings:

    Setting Value
    Auth base URL https://account.sainsburys.co.uk/
    Discovery https://account.sainsburys.co.uk/.well-known/openid-configuration
    Authorization endpoint https://account.sainsburys.co.uk/oauth2/auth
    Token endpoint https://account.sainsburys.co.uk/oauth2/token
    Scopes openid offline gol-session
    PKCE code_challenge / code_verifier, method S256

    Identity stack uses Ory Hydra behind Akamai. Discovery/token endpoints may return 403 to unauthenticated curl; browsers and the app fetch discovery at runtime.

    Android login flow (AppAuth)¶

    1. App opens browser/WebView to account.sainsburys.co.uk/oauth2/auth with the Android client params.
    2. User authenticates; redirect returns authorization code to sainsburys://oauth/redirect-login.
    3. App exchanges code for tokens at token endpoint (access_token, refresh_token, id_token, expires_at).
    4. App calls POST /groceries-api/gol-services/login/v1/login-access-token to obtain commerce session tokens.

    Desktop web login flow (gol-ui)¶

    Captured from Chrome DevTools (Aug 2026):

    1. GET /oauth2/auth?client_id=gol&redirect_uri=…/gol-ui/oauth/redirect&… → Hydra login challenge.
    2. GET /gol/login?login_challenge=<uuid> — login form (React login-ui).
    3. POST /gol/login — form fields: login_challenge, username, password, web_authn_device=0, optional ioBlackBox (Iovation/Glassbox fraud signal).
    4. If MFA enabled: 302 → /gol/login/mfa, then POST /gol/login/send-mfa to trigger code delivery, then POST /gol/login/mfa with code (+ optional ioBlackBox).
    5. Success: 302 → /oauth2/auth?…&login_verifier=<uuid> → redirect to https://www.sainsburys.co.uk/gol-ui/oauth/redirect?code=…&state=….
    6. Exchange code at /oauth2/token, then commerce session via POST …/login/v1/login-access-token.

    pysainsburys implements this via GOLAuth with login(), request_mfa_code(), send_credentials(), and send_mfa_request(). The ioBlackBox field is generated by third-party browser JS and may be required for automated login to succeed.

    Login access token exchange¶

    POST /groceries-api/gol-services/login/v1/login-access-token

    Request body (LoginAccessPayload):

    {
  "access_token": "<oauth_access_token>",
  "food_profile_create": true
}

    Response (WCSTokenEntity):

    {
  "personalization_id": "string | null",
  "user_id": "string",
  "wc_token": "string | null",
  "wc_trusted_token": "string"
}

    These WC tokens establish the WebSphere Commerce session used by subsequent grocery API calls.

    Authenticated request headers¶

    The app attaches different header sets depending on context:

    Header When Source
    Authorization: Bearer <token> Authenticated grocery API calls OAuth access token or refreshed token
    refresh_token: <token> Token refresh flows Stored refresh token
    Cookie: <cookies> Session-bound requests Cookie jar for www.sainsburys.co.uk
    WCAuthToken: <token> Commerce session {user_id},{wc_trusted_token} URL-encoded (e.g. 682092082%2Cmcvf…)
    User-Agent: GOLAppAndroid/<version> All grocery API calls Hardcoded app version (live: GOLAppAndroid/3.65.0)
    X-acf-sensor-data: <sensor> Requests to pinned hosts Akamai BMP SDK (libakamaibmp.so)
    X-SmartShop-Channel: gol api.gs.sainsburys.co.uk requests Ktor plugin (hardcoded)

    Pinned / sensor-protected hosts (Akamai BMP applies X-acf-sensor-data):

    • www.sainsburys.co.uk
    • account.sainsburys.co.uk
    • api.gs.sainsburys.co.uk
    • gol-app-bff-commerce.int.prd.jspaas.uk
    • gol-app-bff-homepage.int.prd.jspaas.uk
    • (and CitrusAd, ChopChop, reviews hosts)

    SmartShop (in-store) — barcode lookup¶

    Base: https://api.gs.sainsburys.co.uk

    SmartShop is the only in-app path that resolves a scanned EAN to product data. There is no separate “lookup by barcode” endpoint: the app scans via ML Kit (libbarhopper_v3.so), then POSTs the raw EAN as itemId to the basket API. The server resolves the product and returns a ShopDTO whose embedded.basket contains line items with names, prices, etc.

    Required headers¶

    Header Value Notes
    Authorization Bearer <OAuth access token> Same OIDC token as grocery API (Session.getToken()), not WCAuthToken
    X-SmartShop-Channel gol Injected by Ktor plugin on all api.gs.sainsburys.co.uk requests
    X-Store-Id e.g. 0474 Store context on basket/shop calls
    User-Agent GOLAppAndroid/3.65.0 Optional spoof: sdk_gphone64_arm64, Android 35, SmartShop Android 3.66.1 (debug flag)
    Content-Type application/json On POST/PATCH bodies

    Local EAN cache¶

    SmartShop maintains SQLite table SmartShopEans mapping generic ↔ actual EAN for loose produce (barcodes that encode weight/price). Entries expire after 15 days.

    Product Finder (in-store search, not barcode)¶

    Base: https://www.sainsburys.co.uk/product-finder

    Separate UI feature (ProductFinderFragment) for text search with aisle/stock info in a chosen store. Uses the same OAuth Bearer session as grocery API.

    Method Path Notes
    GET /v1/products/store/{storeId}?keyword={q}&page={n}&size=20 Legacy
    GET /v2/products?storeId={storeId}&keyword={q}&page={n}&size=20 Default when remote flag ProductSearchV2/V3 active
    GET /v3/products?storeId={storeId}&keyword={q}&page={n}&size=20 Newer variant
    GET /v2/products/batch?storeId={storeId}&productIds={uid,uid} Batch by product UID, not EAN

    API version selected by remote config flags (ProductSearchV1 / V2 / V3).

    Live probe status (2026-08-30)¶

    Query Result
    keyword=milk, storeId=0474, page=1 200 — full product list with aisle/stock
    keyword=<EAN>, same params 200 — content: [] (EAN not accepted as keyword)
    page=0 400 Validation failure

    Product Finder is useful for in-store text search but does not expose barcode lookup.

    Barcode lookup (online workaround)¶

    Sainsbury's has no public EAN search endpoint. Products include eans[] in responses, but lookup is only by UID or keyword.

    Recommended approach (pyukgroceries pattern)¶

    Prior art: pantherale0/pyukgroceries.

    Step Service Call
    1. Barcode → name Open Food Facts GET https://world.openfoodfacts.org/api/v2/product/{ean}.json
    2. Name → candidates GOL product search GET …/product/v1/product?filter[keyword]={brand} {name}&page_number=1&page_size=24
    3. Disambiguate Client-side filter Keep products where {ean} ∈ eans[]

    Search endpoint (legacy v1, still works unauthenticated):

    GET /groceries-api/gol-services/product/v1/product?page_number=1&page_size=24&filter[keyword]=QUERY
User-Agent: GOLAppAndroid/3.65.0
Accept: application/json

    Response: { "products": [ { "product_uid", "name", "eans", "retail_price", … } ], "controls": … }

    Validated: EAN 8002270018213 → OFF name → keyword search → uid 6731637 with matching EAN.

    Caveats: Open Food Facts coverage gaps; ambiguous names may return sibling SKUs until EAN filter runs; loose-weight barcodes may not appear in OFF or Sainsbury's catalogue.

    Protections affecting direct API use¶

    1. Akamai BMP — X-acf-sensor-data header required on protected hosts; generated by native SDK.
    2. Certificate pinning — OkHttp CertificatePinner on grocery API clients.
    3. OAuth + WC tokens — Two-layer auth: OIDC bearer token + commerce session (WCAuthToken, cookies).
    4. Play Integrity — Referenced for device attestation (exact enforcement TBD via live capture).
